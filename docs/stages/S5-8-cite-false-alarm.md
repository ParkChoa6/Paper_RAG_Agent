## §1 改了什么

### 1.1 `paper_rag/cite.py` —— 归一化函数（核心）

[`paper_rag/cite.py:58-118`](../../paper_rag/cite.py#L58-L118)，`_norm`：

```python
# 旧版（2026-09 ~ 2026-10-12）
return " ".join(re.sub(r"[^\w\s]", " ", s.lower()).split())
#   = 转小写 / 标点换空格 / 压空白      ← ★ 保留【词间空白】

# 新版
_MARKER_RE = re.compile(r"^\[\d+\]\s*")
return re.sub(r"[^\w]", "", _MARKER_RE.sub("", s.strip()).lower())
#   = 剥掉开头的 "[n] " + 只保留 \w（空白和标点【全删】）
```

两个改动，各治一个病：

| 改动 | 治什么 |
|---|---|
| 空白从"压成一个"改成"全删" | PDF 丢空格、PDF 连字符断行 |
| 剥掉开头的 `[n]` 标记 | 模型把材料表头的编号一起抄进 quotes |

### 1.2 `paper_rag/cite.py` —— ④ 的判定分支

[`paper_rag/cite.py:306-380`](../../paper_rag/cite.py#L306-L380)。

原来：找不到 → 一律 `"引用 [n]：原文中找不到对应内容（疑似伪造）"`。

现在：找不到之后**再去同批的别条材料里搜一遍**：

```

搜不到  → "引用 [n]：原文中找不到对应内容（疑似伪造）"     ← 文案没变
```

顺带把归一化挪到循环外做一次（`norm_chunks`），因为新分支要用同一条材料去搜 `k` 次。

## §2 为什么这么写

### 2.1 为什么改的是**归一化**，不是加模糊匹配

`verify` 的老 docstring 自己列过三个方案（那份 docstring 我留着）：

| 方案 | 代价 |
|---|---|
| 精确 `in` | 换个标点就误报 → 假警报 |
| 归一化后 `in` | 得定义"归一化到什么程度"，收得越松、伪造越容易蒙混 |
| `difflib` 比阈值 | **阈值是个魔法数字，而且没有明确边界** —— "90% 像"到底算不算引用？你答不上来 |

S5-6 当时选的是方案二。这次发现方案二**收得不够松**，
那直觉上应该跳到方案三。**没有那么做**，理由是：

> 方案三的阈值之所以"答不上来"，是因为它把**两种不同的差别**混在一个连续分数里：
> 一种是**格式**差别（空格、标点、表头）—— 该抹掉；
> 一种是**内容**差别（多一个词、换一个词）—— 该抓住。
>
> 归一化能**说清楚自己抹掉了什么**（"我抹掉了空白和标点"）；
> 阈值说不清（"我抹掉了 10% 的相似度" —— 那 10% 是哪 10%？）。
>
> ★ **能说清楚抹掉了什么，是这一层唯一值钱的性质。**
> 这个校验器的用途是"证明这句话有出处"，它给出的每条结论都要能被人复核。
> 一个答不上来的阈值，等于把复核能力也一起交出去了。

所以走的是"把归一化**继续收紧规格**"这条路：空白全删 + 剥编号。
**每一条抹掉的东西，都能用一句话说出来。**

### 2.2 为什么剥 `[N]` 前缀 —— 而 2026-10-09 我明确拒绝过

这是本阶段最值得看的一处**自我推翻**。老注释原文：

> 为什么不是"把 quotes 开头的 [n] 剥掉"：
> 那是补偿我们自己制造的偏差；表头一改（比如加论文标题），剥离函数就静默失效。

**这个理由对了一半。** 它把两件事当成了一件：

| | 会不会变 | 该不该剥 |
|---|---|---|
| **表头内容**（标题？页码？章节？） | ★ 一直在变（2026-10-10 就加过标题） | 不该写死剥离函数 —— 老注释说的是这个，对 |
| **编号标记 `[n] `** | ★ 语法是我们定的，`^\[\d+\]`，**永远不会变** | 该剥 —— 老注释把这条也一起否了，错 |

而它**每次都会被模型抄下来**，因为我们就把它印在材料第一行。
模型分不清"哪里算材料"——这句话是老注释自己写的。

★ 判据：**「会变的东西」不要写死；「不变的东西」写死它是省事，不是脆弱。**
老注释拒绝的是"贴着会变的东西写死"，顺手把"不会变的东西"也拒了。

**新旧方案其实是一致的**（都不依赖表头），验证见 §4.2：新方案**同时**修好了
表头类（Q1/Q6）和空白类（Q8/Q26），一个函数，两个病。

### 2.3 为什么「编号错配」要做成 `verify` 的一种报错，而不是留在评测脚本里

S5-6 已经在 `eval_answer.classify_citations` 里做过这件事了，而且它的 docstring 写得很对：

> **有损压缩不可逆** —— 不在这里分开，事后就再也分不开了。

**那为什么不继续放在那儿？** 因为它是**评测脚本**：只有跑评测的时候才执行。
生产路径 `scripts/ask.py` 走的是 `pipeline.ask()` → `verify()`，
用户在看到 `[2]` 这条报错时，**拿到的还是那句"疑似伪造"**。

一句话：**诊断写在评测脚本里 = 只有评测的时候有诊断。**
把它移进 `verify`，生产路径上每个用户都拿到分好类的报错。

★ 但 `classify_citations` **没有删**，因为它还管着 `verify` 管不了的一件事 —— 见 §2.4。

### 2.4 为什么 `verify` 只在【本次材料】里搜，不去搜全语料

`classify_citations` 的 docstring 特意说了它用**全语料**：

> 判据用【全语料】而不是【本次材料】：这样"引错编号"才和"幻觉"分得开。

**它说的对，但那是另一个问题。** 两者的 scope 不一样，都不是错：

| | 搜哪儿 | 回答的问题 | 结果 |
|---|---|---|---|
| `verify` | **本次材料** | "这句话在你给我的这批材料里吗" | 不在 → 疑似伪造 |
| `classify_citations` | **全语料** | "这句话在这个知识库里吗" | 在 → 模型是**凭记忆引的**，不是编的 |

`verify` **拿不到**全语料（它的签名只有 `parsed` 和 `chunks`），
而且**不该拿** —— 它的规格是"模型只见过这批材料"。
对这条规格来说，"语料里别处有"**不构成辩护**：模型没有看到它，
却把它当成"你给的材料"引用了，那仍然是伪造。

★ 而"它其实是模型背下来的"这件事**对修法有用**（说明要改的是提示词而不是模型能力），
所以 `classify_citations` 留着，作为**更深一层**的诊断。
两层，两个 scope，各说各的话。

### 2.5 为什么没顺手把 `verify` 的返回值改成结构化对象

`verify` 返回 `list[str]`，现在文案有 5 种。下游有两处靠**字符串匹配**认病：

- `scripts/probe_cite.py:490` — `[p for p in probs if "疑似伪造" in p]`
- `scripts/eval_answer.py` — `re.search(r"引用 \[(\d+)\]", p)`

改成 `list[Problem]`（带 `kind` / `n` / `m` 字段）确实更结实。
**这次没改**，理由是这一阶段的变量已经够多了（归一化 + 新分支 + 探针规格 + 类名），
再动返回类型，会让"到底是哪一处改动让数字变了"说不清。

★ 但这笔债记在 §7.2 —— 文案一改，下游静默失配（`"疑似伪造" in p` 会变成永远 False，
**不报错**），这是典型的"下次会咬人"。

## §3 不应该怎么写

### 3.1 ❌ 只删空白，不剥 `[N]`

```python
def _norm(s): return re.sub(r"[^\w]", "", s.lower())     # 少了 MARKER_RE.sub
```

**症状**：684 条里只修掉 11 条，**剩下 8 条继续假报警**（oracle Q1、Q6，rerank Q6…）。
你会看到"误报从 56 降到 45 了，有进步"，然后收工 ——
而剩下那 8 条**长得和修好的那 11 条一模一样**（都是"句子确实在材料里"），
你没有任何理由觉得它们不一样。

★ 这正是本阶段的教训：**"数字变好了"和"病治完了"是两件事。**
先分类，再改；分类告诉你一共有几种病。

### 3.2 ❌ 用 `difflib` 阈值替掉 `_norm`

```python
if difflib.SequenceMatcher(None, q, c).ratio() > 0.9: ...   # 0.9 是拍的
```

**症状**：三件事同时发生，而且**都不报错**——

1. 0.9 是拍的。语料一换（比如换成中文论文），这个数就不对了，没人知道。
2. 你要判"0.9 算不算引用"，**但你答不上来**。于是这个数会一直被调，每次都"感觉好点了"。
3. ★ 最坏的一种：**真伪造里那些"很像原文"的会被放行。**
   实测里有这么一条 —— 模型把 PDF 断行的 `causality` 抄成了 **`causalcity`**（多一个 `c`）。
   按归一化判，它**是伪造**（正确）；按相似度判，这一条和原文像到 **0.99**，
   **会被放行**。一个字母的差别，正是相似度最看不见的东西。

### 3.3 ❌ 把「编号错配」也报成「疑似伪造」（= 改之前的状态）

**症状**：你会拿着**「这个模型会编造引用」**这个结论去改提示词 ——
而真正的病是**"它先把句子写出来了，然后随手贴了个编号"**。
药完全不一样（前者要收模型，后者要改契约的执行顺序）。

★ 这个错法**当时就写在评测脚本的注释里**，说明 S5-6 已经诊断出来了，
只是诊断没有走到生产路径上（§2.3）。

### 3.4 ❌ 在 `verify` 里搜全语料

**症状**：

1. 签名要变（得把整个语料传进来），而 `verify` 每次请求都跑 —— 每次全库扫。
2. ★ 更糟的是**判断会变错**：它会开始说"这句话语料里有，不算伪造"。
   可模型**没看到语料**。这句话对模型来说是**凭空出现的**。
   你会亲手给这台校验器开一个后门，而它看起来像是"降低了误报"。

### 3.5 ❌ 只测「改完之后还剩几条不匹配」

只跑 §4.2 那张表（56 → 37），结论会是"误报少了，收工"。

**症状**：你**不知道**校验器有没有变松到放行伪造。
而这**恰恰是唯一值得担心的事** —— 一个什么都放行的校验器，
报错率是 **0**，看起来完美。

★ **放松判据的改动，必须配一个"构造的伪造还抓不抓得住"的测试。**
本阶段用的是 `probe_cite.py` 的离线 9 关 + 实验 A 的诱导伪造（§4.4）。
这也是为什么**探针要独立实现、不能 import**：`probe_norm` 若直接 import `cite._norm`，
它就只能证明"verify 没崩"，证明不了"verify 判对了"。

### 4.4 ★★ 安全测试：改松之后，伪造还抓不抓得住

这是**本阶段最该看的一张表**。放松任何判据都必须配它。

`probe_cite.py` 的实验 A 会**诱导**模型给出伪造引用（把拒答规则拿掉，改成"quotes 不许为空"），
然后用**探针自己独立实现的** `probe_norm` 数一遍伪造条数，再和 `verify` 报的条数对拍：

```
实验 A 汇总（2 题 × 4 seed = 8 次）
  编造被抓    5 次
  两边对不上   0 次   ← 这一项必须为 0，否则 verify 有问题

✅ 通过，且诱导有效（5/8 次编了，verify 每次抓住）。
   退出码 = 0
```

**5 次伪造，5 次全抓住。** 判据松了，但没松到放行伪造。

★ **探针在这里响了**，而且响得对：`probe_norm` 的规格是抄 `cite._norm` 的 docstring 写的，
我改 `_norm` 之后两份规格就不一致了，**"两边对不上"这一项会变成非 0** ——
探针把我自己引入的规格漂移摊到了台面上。
它的 docstring 原本就写着这句话：「★ 这也是个警报器：哪天 verify 的 `_norm` 改了…」。

### 4.5 ★ 生产路径的现场证据

改完之后跑一次真实提问：

```
$ ./.venv/Scripts/python.exe scripts/ask.py "RotatE 把关系建模成什么操作？"
  [1] RotatE [94] models entities in the complex vector space and interprets relations as rotati
  ✓ 引用校验通过（每条 quotes 都能在材料原文里找到）
```

把这条 quote 拿回去喂给新旧两个 `_norm`：

```
旧 _norm：quote 在材料里? False     ← 会报「疑似伪造」
新 _norm：quote 在材料里? True      ← 通过
```

**★ 这不是构造的例子，是生产系统当场吐出来的。**

## §5 你要补的概念

### 5.1 归一化 = "把不重要的差别定义为不存在"

子串匹配 `q in c` 的问题不是"太严格"，是**它假设"重要的差别"和"字符的差别"是同一件事**。
归一化做的事情是：**先声明什么不重要，再比对。**

关键不是"归一化到什么程度"，是**你能不能说清楚归一化抹掉了什么**：

| 归一化抹掉 | 能不能一句话说清 | 评价 |
|---|---|---|
| 大小写、标点、空白 | "格式差异" | ✅ 可以 |
| 开头材料表头的 `[n]` | "我们自己印上去的编号" | ✅ 可以 |
| "相似度低于 10% 的部分" | **说不清** | ❌ |

★ 所以 §3.2 否掉 `difflib` 的理由**不是"不够准"**，是"**说不清它抹掉了什么**"。

### 5.2 ★ 材料可能比模型还脏 —— 而模型会"修好"它

这是本阶段最反直觉的一条。我们一直默认"原文是标准，模型是可能出错的一方"。
实测：

| 原文（PDF 抽出来的） | 模型抄回来的 |
|---|---|
| `Amongthem,65.31%oftheinductivemodels` | `Among them, 65.31% of the inductive models` |
| `knowl` + 软连字符 + 换行 + `edge` | `knowledge` |
| `causal` + 软连字符 + 换行 + `ity` | `causality` |

前两条：**模型是对的，材料是坏的。** 而校验器站在材料这边，判模型伪造。

**为什么模型能"修好"**：它是**按 token 生成**的，不是**按字符复制**的。
它看到 `knowl` + 软连字符 + 换行 + `edge`，内部拼出的是正常的词 `knowledge`，
输出时按正常拼写吐出来 —— 它**根本没有能力**逐字符忠实复制。
★ 「让模型逐字抄原句」这个要求在 token 级别**不可能被满足**。

**但它也不是每次都修对**：第三条它吐出了 `causalcity`（多一个 `c`）——
**同一个机制，修对是它、修错也是它。** 而这一条被校验器**正确抓住**了。

★ 结论：**别把"原文"当无损的 ground truth。** 校验器比的是两段文本，
其中一段在我们读它之前就已经被 PDF 抽取弄坏了 ——
这件事得先量清楚（684 条），才知道该往哪边修。

### 5.3 有损压缩不可逆

`verify` 原来对三种病输出**同一句话**。S5-6 的注释写得很准：

> 三种病的药完全不同，而 `verify` 的输出把它们糊成了一个布尔。**有损压缩不可逆** ——
> 不在这里分开，事后就再也分不开了。

★ 但 S5-6 的处理是"**在别处**再算一遍"（评测脚本里）。那是**可以**的，只是有代价：
**只有跑评测的时候才有这个信息。** 本阶段把它搬回了"产生信息的那一层"。

一般化的判据：**信息该在哪一层被区分开？—— 在它第一次被看见的那一层。**
晚一层区分，就要靠重新计算来还原，而重新计算依赖"当时的数据还在"。

### 5.4 报警疲劳

假警报的代价不是"多看一眼"，是**训练人无视警报**。
19/56 = 34% 的报错是假的 —— 这个比例足以让人形成"它老瞎报"的印象，
然后**真伪造（那 2 条）就被一起无视了**。

★ 一个 34% 假阳性的安全组件，实际防护力**低于**一个 0% 假阳性但少报一半的组件。
`config.py` 里那条「报警疲劳」讲的是同一件事。

### 5.5 探针：独立实现对拍 vs import 复读

| 写法 | 能证明什么 |
|---|---|
| `from cite import _norm` | 只能证明"verify 没崩" |
| ★ 自己按 **docstring** 重写一遍规格 | 能证明"**规格**被实现了"，并在规格漂移时**叫醒你** |

★ 关键在**规格写在 docstring 里**（自然语言），实现是**另一份**。
改动 `_norm` 的人（是我）本来只想动 `cite.py`，是探针把"规格变了"这件事摊出来的。

## §6 自测题

**Q1（预测行为）** —— 下面两条 quote，用**新版** `_norm` 判，哪条通过？

```
材料原文：  "[1] （A Survey of KG Reasoning，第 8 页）RotatE models entities in the complex space."
甲： "[1] RotatE models entities in the complex space."
乙： "RotatE models entities in the complex space."
```

**Q2（预测行为）** —— 某条 quote 是 `"The model achieves 91.5% accuracy on FB15k-237."`，
本次材料共 5 条，第 1 条里有这一句，但模型把它挂在 `[3]` 上。`verify` 会报什么？**为什么不是"疑似伪造"？**

**Q3（判断）** —— 有人提议：既然搜全语料能降低误报，干脆把整个语料传给 `verify`。
用一句话说清**为什么不行**。（提示：`verify` 的规格是什么？模型看到的是什么？）

**Q4（判断）** —— 下面的改动能不能接受？

```python
if difflib.SequenceMatcher(None, q, c).ratio() > 0.85:   # 通过
```

（提示：§4.3 里那条 `causalcity` 会被怎么判？）

**Q5（找漏洞）** —— `verify` 的报错文案现在有 5 种。下游 `probe_cite.py` 是这么认病的：

```python
v_forged = [p for p in probs if "疑似伪造" in p]
```

如果哪天有人把文案改成「疑似编造」，会发生什么？**会报错吗？**

---

<details>
<summary>参考答案</summary>

**A1** —— **两条都通过。** 新版 `_norm` 先把开头的 `[n] ` 剥掉（甲变成 `RotatE models…`），
再把所有非 `\w` 字符（空白、标点、`（` `）`）全删。
甲的正文和乙完全相同，两者都能在材料的正文里找到。
★ 而**旧版**：甲会**通过**（因为旧版基线是 `render_material`，含表头 `[1] `），
乙也会通过 —— 但**甲要是写成 `[1] RotatE…` 而表头里又插了标题**（真实情况就是这样），
旧版就判 False。这题的重点是：**新版不再依赖表头里放了什么**。

**A2** —— 报 **`引用 [3]：原句不在材料 [3] 里，实际出自材料 [1]（编号错配，不是伪造）`**。
不是"疑似伪造"，因为**句子确实在这批材料里**，模型看过它 —— 它的错是"贴错编号"，
不是"编了一句话"。两种病的药不同（编号错配 → 改契约执行顺序；伪造 → 收模型）。

**A3** —— 因为 `verify` 的规格是**「模型只见过这批材料」**。
模型没看到全语料，所以"语料里别处有"**不构成辩护** —— 对模型来说那句话是凭空出现的，
仍然是伪造。传全语料等于**给校验器开后门**，而且它看起来像"降低了误报"。
（"它其实是模型背下来的"这件事有用，但那是**诊断**，不是**判定** —— 所以留在
`classify_citations`，不进 `verify`。）

**A4** —— **不能接受。** `causalcity` 和原文 `causality` 只差 1 个字母，
相似度约 **0.99 > 0.85 → 放行**。而它**确实是伪造**（模型抄错了）。
★ 一个字母的差别，正是相似度最看不见的东西。
另外 0.85 是拍的，语料一换就失效（换中文论文时这个数完全不对）。

**A5** —— **不会报错。** `"疑似伪造" in p` 会**永远为 False**，于是 `v_forged` 永远是空表，
探针会开始报「这一次模型没编引用」→ 走到 `EXIT_UNTESTED`（退出码 2），
或者更糟：**"两边对不上"这一项永远是 0**，探针显示全绿。
★ 这是**字符串匹配当接口用**的典型故障：改文案 = 静默改协议。
正解是结构化返回（`kind` 字段），见 §7.2。

</details>
