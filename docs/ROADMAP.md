## 三、阶段详情

### Stage 0A · Python 最小必要集

**为什么要这一段**：RAG 项目里 `Retriever`、`Splitter` 全是类，跨文件 `import` 是日常。基础不补，后面每一步都在抄代码而不是写代码。

**只补这个项目绕不开的**，每课配一个跟 RAG 直接相关的练习：

| 课 | 内容 | 在项目里对应什么 |
|---|---|---|
| 0A-1 | dict 与 list | 一个 chunk 就是 `{"text": ..., "page": 3, ...}` |
| 0A-2 | 函数与返回值 | `split_pdf(path) -> list[dict]` |
| 0A-3 | 类与对象 | `Retriever`、`PDFLoader` 都是类 |
| 0A-4 | 模块与 `import` | 项目要拆成多个文件 |
| 0A-5 | 异常处理 | PDF 解析失败、模型调用超时 |
| 0A-6 | 文件读写与 JSON | 存知识库、存评测集 |
| 0A-7 | 虚拟环境与依赖 | 项目环境的隔离与复现 |

**明确跳过**：装饰器、异步、元类、推导式进阶、多线程 —— 用到时再补。

**验收**：能独立写出上面 7 项对应的小程序，并解释每一行为什么这么写。

### Stage 1 · 文档接入

**内容**

- PDF 解析（PyMuPDF）
- 学术论文特有的坑：双栏排版、公式、表格、页眉页脚、参考文献
- 切分策略：固定长度 / 递归 / 按章节结构
- **元数据设计**：`paper_id` / `page` / `section` / `chunk_id`

**为什么元数据是重点**：它是后面"引用原文"能否实现的**唯一前提**。这里偷懒，Stage 4 要推倒重来。

**验收**：喂进一篇真实论文，输出带完整元数据的 chunks，且**页码准确**。

---

### Stage 2 · 向量化与检索

**内容**

- Embedding 是什么、为什么需要它
- 余弦相似度
- **先用 numpy 手写一遍暴力检索**
- 再换成向量库（FAISS）

**为什么先手写**：你才会知道向量库到底替你做了什么。否则它就是个黑盒。

**验收**：手写检索的结果与向量库一致，并能解释"为什么索引能加速"。

---

### Stage 3 · 朴素 RAG

**内容**

- 检索 → 拼 prompt → 调 LLM → 输出
- Prompt 设计：上下文注入、**拒答**、格式约束

**硬性要求：不许用 LangChain。** 全手写一遍，你会看清 RAG 的真实面目就是一个 for 循环加一次 API 调用。之后再用框架，你是"选择"用，不是"只能"用。

**验收**：对一篇论文提问能得到基于原文的回答；问论文里没有的内容时**会拒答**，而不是编造。

---

### Stage 4 · 引用溯源

**内容**

- 让模型输出结构化引用（而非自由文本）
- chunk → 原文的映射与回显
- **引用真伪校验**：生成的引用是否真的存在于检索结果中

**会做的实验**：故意构造一个让模型编造引用的场景，亲眼看一次幻觉。对幻觉的切肤之痛，比任何警告都管用。

**验收**：每条引用都能点回原文；能自动检出模型伪造的引用。

---

### Stage 5 · 检索质量

**内容**

- **先建评测集**（这一步必须在所有优化之前）
- 指标：recall@k、MRR
- 混合检索：BM25 + 向量 + RRF 融合
- Rerank：cross-encoder
- Query 改写：HyDE、multi-query

**核心工程认知**：没有评测集，你所有的"优化"都只是感觉。

**验收**：有一套评测集，任何改动后都能**定量**说明是变好还是变坏。

---

### Stage 6 · Agent 化

**内容**

- 从固定 pipeline 转向**工具调用循环**
- 工具设计：`search_papers`、`get_metadata`、`compare_sections`
- Function calling 协议
- 循环控制：最大步数、失败重试、死循环防护
- 记忆：短期对话 + 长期

**验收**：Agent 能自己判断该调什么工具、调几次，完成一个多步任务。

---

### Stage 7 · 多论文分析

**内容**

- 跨文档检索
- 论文对比、综述生成
- Map-reduce / refine 策略
- 引用聚合与去重

**验收**：给 5 篇论文，能生成一份带引用的对比综述。

---

### Stage 8 · 工程收尾

**内容**

- FastAPI 服务化
- 界面（Streamlit / Gradio）
- 缓存、并发、成本控制
- 可观测性：追踪每一次检索与生成
- 部署

**验收**：别人能照着 README 把它跑起来。

---

## 四、贯穿全程的东西

不单独开课，而是每一步都渗透：

- 抽象与接口设计（为什么要有 `Retriever` 这个接口）
- 配置化 vs 硬编码
- 可测试性 / 可观测性
- **成本 / 延迟 / 准确率的三方权衡**
